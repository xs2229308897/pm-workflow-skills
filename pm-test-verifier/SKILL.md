# 测试验证 Agent

根据 PRD 生成测试用例，指导测试执行。独立执行，不参与动态反馈循环。

## 输入

- PRD 文档（功能设计、接口定义）
- 原型代码（来自原型开发 Agent）

## 处理流程

1. 根据 PRD 功能设计生成测试用例清单
2. 为每个接口定义预期请求/响应
3. 生成冒烟测试步骤
4. 生成自动化测试脚本（Playwright TypeScript，覆盖核心流程和冒烟测试）
5. 记录测试结果和发现的问题

## 自动化测试脚本规范

基于 Playwright + TypeScript 生成 E2E 测试脚本：

- **文件位置**：`tests/e2e/` 目录下，按模块组织
- **命名规范**：`{模块名}.spec.ts`
- **覆盖范围**：冒烟测试（核心流程）+ 关键功能点
- **脚本结构**：
  - 使用 `test.describe` 按功能模块分组
  - 使用 `test.beforeEach` 做公共前置（如登录）
  - 每个测试用例包含：前置条件、操作步骤、断言验证
  - 使用 Page Object 模式组织页面交互（如页面复杂度需要）

## B 端测试维度（仅 B 端模式）

在标准测试用例之外，增加以下 B 端专项测试：

| 测试类型 | 测试内容 | 验收标准 |
|---------|---------|---------|
| 多租户数据隔离 | 租户 A 不能看到租户 B 的数据 | 所有 API 和页面均需验证 |
| 权限边界测试 | 越权操作验证（低权限用户访问高权限功能） | 所有受保护功能均需覆盖 |
| 审批流完整性 | 多级/会签/回退/超时自动处理 | 所有审批路径均需验证 |
| 批量数据性能 | 批量导入/导出/审批的性能 | 万级数据量下响应时间可接受 |
| 并发操作测试 | 多用户同时操作同一资源 | 无数据丢失或状态异常 |
| 数据迁移验证 | 源系统 → 目标系统的数据完整性 | 字段映射正确、数据无丢失 |
<!-- B-MODE-END -->

## 输出格式

1. 测试用例清单（编号、功能点、步骤、预期结果）
2. 冒烟测试清单
3. 自动化测试脚本（Playwright TypeScript，可直接运行）
4. 问题清单模板

## 自审清单

- 测试用例是否覆盖了所有功能点？
- 冒烟测试是否覆盖了核心流程？
- 测试步骤是否可执行？
- 自动化测试脚本是否覆盖了冒烟测试用例？
- 自动化脚本是否使用了正确的页面选择器（与原型代码匹配）？
<!-- B-MODE-START -->
**B 端自审项（仅 B 端模式）：**

- 是否包含多租户数据隔离测试？
- 是否包含权限边界测试？
- 是否包含审批流完整性测试？
- 是否包含批量数据和并发操作测试？

## 汇报格式

- 产出：测试报告
- 缺口：如有
- 自审发现：如有
