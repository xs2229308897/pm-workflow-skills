## 一、标准 Agent（10 个）

### 1. pm-leader — PM 领导者

| 维度 | 内容 |
|------|------|
| **人设** | 资深产品总监，你唯一需要对话的入口。沉稳、有条理，擅长识别用户意图、分解任务、调度专家、汇总成果。像一位经验丰富的 PM 团队负责人——不会一次性列出所有问题让用户焦虑，而是逐项引导；不会盲目信任下属的汇报，而是亲自验证产出质量后再交给用户。 |
| **核心职责** | 意图识别 → 任务分配 → 产出验证 → 成果汇总 → 学习进化 |
| **功能介绍** | ① 自动识别用户输入意图，匹配对应子 Agent 并构造专业 prompt 调度执行；② 支持并行调度（需求分析∥竞品分析，风险评估∥数据建模∥权限设计）和串行编排（PRD→架构→流程→原型→测试→反馈）；③ 自动验证子 Agent 产出质量（非空检查、必填章节完整、无 TODO/TBD 占位符），不合格产出自动重调度；④ 双层经验教训系统：启动时自动同步 GitHub 上的全局教训，与本地项目教训合并后注入子 Agent prompt；⑤ 6 项首次启动检查：原型模板配置 → 状态文件 → 教训文件 → 产出目录 → Hooks 配置 → B 端模式开关，逐项引导；⑥ 会话中断后检测快照文件，提供一键恢复；⑦ MCP 能力注册：自动检测可用外部工具（Brave Search、Figma、数据库、pm-workflow-tools）并注入子 Agent；⑧ 动态反馈循环：任一子 Agent 发现缺口可请求领导者重新调度上游 Agent 补充。 |

### 2. pm-requirement-analysis — 需求分析专家

| 维度 | 内容 |
|------|------|
| **人设** | 严谨的系统分析师，擅长从混乱的原始信息中提炼结构化需求。面对微信聊天记录、会议纪要、语音转文字等非结构化文本时游刃有余，能从嘈杂信息中识别真正的需求信号。追求"不遗漏、不重复、可执行"。 |
| **核心职责** | 提取需求点 → 模块分类 → 去重合并 → 优先级标注 → 隐含需求补充 |
| **功能介绍** | ① 从非结构化文本中识别所有需求点，按模块/功能分类并去重合并；② 为每个需求标注优先级（高/中/低）、编号（M{模块}-{序号}）、验收标准和来源出处；③ 自动补充隐含需求（如"数据展示"隐含"数据导出"需求）；④ 支持调用 MCP 工具 `assess_requirement_quality` 自评质量（0-100 分），低于 70 分自动优化；⑤ **B 端模式增强**：额外支持 RFP/招标文件、业务流程图、组织架构描述等输入源；新增按角色/租户层级/业务流程三维分类；补充企业级隐含需求（操作日志、批量操作、异常恢复、多端适配、通知机制）。 |

---

### 3. pm-competitive-analysis — 竞品分析专家

| 维度 | 内容 |
|------|------|
| **人设** | 敏锐的市场情报分析师，对行业格局了如指掌。善于从公开信息中发现竞品的优势与软肋，为产品定位提供数据支撑。不满足于表面功能对比，追求深层的差异化洞察。 |
| **核心职责** | 竞品搜索 → 功能对比 → 差异化分析 → 功能建议 |
| **功能介绍** | ① 支持通过 MCP web-search 工具实时搜索竞品信息（结构化查询），无网络时回退至训练数据中的行业知识；② 生成竞品概览（名称、核心功能、优劣势）和功能对比矩阵（我方 vs 竞品）；③ 识别差异化机会，提出可操作的功能建议；④ **B 端模式增强**：额外输出供应商对比表（厂商规模/行业聚焦/融资）、TCO 总拥有成本分析（许可证+实施+维护+定制+运维）、部署模式对比（SaaS/私有化/混合云）、合规认证对比（SOC2/ISO27001/等保/GDPR）、集成生态对比（API/连接器/Webhook/SSO）、RFP 响应建议。 |

---

### 4. pm-prd-writer — PRD 撰写专家

| 维度 | 内容 |
|------|------|
| **人设** | 资深产品文档架构师，对 PRD 的结构和质量有近乎偏执的要求。坚信一份好的 PRD 应该让开发团队无需追问就能直接编码。对复杂逻辑的描述能力极强，擅长用计算逻辑、业务规则、状态流转图把功能讲透。 |
| **核心职责** | 按模板组织 PRD → 功能详细设计 → 复杂逻辑说明 → 数据模型概要 → 非功能性需求 → 一致性自审 |
| **功能介绍** | ① 生成标准 8 章 PRD：文档头信息 → 执行摘要 → 业务背景与目标 → 范围定义 → 关键功能设计 → 功能逻辑说明 → 数据模型概要 → 非功能性需求；② 对复杂功能强制展开详细逻辑说明：触发条件、处理步骤、输出结果、异常处理（覆盖计算逻辑、业务规则、状态流转、边界条件、数据关联五类场景）；③ 支持调用 MCP 工具 `check_prd_consistency` 自审一致性；④ **B 端模式增强**：标准 8 章基础上新增 4 个 B 端章节——多租户架构方案（隔离模式选择+租户管理+配置隔离）、权限矩阵（角色×功能×数据范围三维表+SSO/LDAP集成方案）、系统集成接口规范（API契约+Webhook事件+数据同步策略）、部署与运维方案（部署方式+环境要求+监控告警）；非功能性需求增强（SLA指标/数据加密/审计日志/数据脱敏/并发预期/扩展方案）。 |

---

### 5. pm-architecture-designer — 技术架构设计师

| 维度 | 内容 |
|------|------|
| **人设** | 经验丰富的系统架构师，在技术选型和架构设计上既有广度又有深度。不做过度设计，也不忽视技术风险。每个架构决策都有清晰的"选择理由+备选方案"，让 PM 和开发团队都能理解。 |
| **核心职责** | 架构风格确定 → 模块划分 → API 规范设计 → 技术选型 → 部署架构 → 技术风险识别 |
| **功能介绍** | ① 分析 PRD 确定架构风格（单体/模块化单体/微服务/Serverless），输出选择理由；② 模块划分与依赖设计（Mermaid C4 上下文图 + 模块依赖图 + 通信方式）；③ API 规范设计（端点清单 + 认证方案 JWT/OAuth2/API Key + 错误码规范 + 版本策略）；④ 技术选型矩阵（前端/后端/数据库/缓存/消息队列，含选择理由和备选方案）；⑤ 部署架构（拓扑图 + 服务组件清单 + 扩展策略 + 环境要求）；⑥ 技术风险清单（性能瓶颈 + 技术债务）；⑦ **B 端模式增强**：多租户架构方案、SSO/LDAP 集成方案、API 网关方案（限流/熔断/版本管理）、数据安全方案（传输加密/存储加密/脱敏规则）。 |

---

### 6. pm-risk-assessor — 风险评估专家

| 维度 | 内容 |
|------|------|
| **人设** | 冷静的风险管理专家，习惯在乐观的 PRD 中找到隐藏的雷区。不唱反调但也不回避问题，每个风险都给出具体缓解方案而非仅标注等级。追求"让 PM 在开发前看清全部风险敞口"。 |
| **核心职责** | 可行性评估 → 跨模块影响分析 → 依赖关系识别 → 风险分级 → 缓解建议 |
| **功能介绍** | ① 对每个需求评估技术可行性和实现复杂度，输出风险等级（高/中/低）和建议；② 跨模块依赖分析：识别需求间的依赖关系和阻塞风险；③ 生成需求风险矩阵（编号、描述、等级、影响模块、建议）；④ 建议需要调整优先级或拆分的需求；⑤ **B 端模式增强**：新增 5 个 B 端专项风险维度——合规风险（等保/GDPR/SOC2）、数据迁移风险（数据质量/字段映射/回滚）、集成风险（第三方 API 稳定性/文档完整性）、客户定制化风险（需求蔓延/定制化对产品化的影响）、上线割接风险（业务中断/数据一致性/回滚预案）；输出增强：风险矩阵增加"缓解方案"列，附送上线前风险检查清单。 |

### 7. pm-data-modeler — 数据建模专家

| 维度 | 内容 |
|------|------|
| **人设** | 严谨的数据架构师，从 PRD 的概要数据模型中展开完整的数据设计。对字段类型、约束条件、实体关系有精准的把控力。知道什么该建模、什么该留白，不做过度的超前设计。 |
| **核心职责** | 实体识别 → 字段定义 → 关系建模 → ER 图生成 → 数据字典输出 |
| **功能介绍** | ① 从 PRD 数据模型概要中提取业务实体，展开为完整数据模型文档（实体列表、完整字段含约束、实体关系、数据流向）；② 支持调用 MCP 工具 `generate_er_diagram` 自动生成 Mermaid ER 图；③ 支持通过 MCP 数据库工具查询现有 schema 作为参考；④ **B 端模式增强**：预置多租户隔离知识（共享表/Schema隔离/数据库隔离三种模式及选型建议）；自动为所有业务实体添加审计字段模板（created_by/created_at/updated_by/updated_at/deleted_at）；自动为数据权限实体添加组织+数据范围字段；软删除模式规范；预置 8 个 B 端通用实体模板（users/roles/permissions/user_roles/role_permissions/organizations/approval_records/operation_logs），确保不遗漏。 |

### 8. pm-prototype-builder — 原型开发工程师

| 维度 | 内容 |
|------|------|
| **人设** | 高效的全栈前端工程师，能用最短的代码生成可运行的产品原型。熟悉多种前端技术栈，严格遵循项目规范。生成的代码不求完美但求可运行、可演示，让 PM 能直观感受产品形态。 |
| **核心职责** | 技术栈读取 → 路由配置 → API 模块 → Mock 数据 → Store 生成 → 页面组件 → 注册路由 → 可运行性验证 |
| **功能介绍** | ① 支持 4 种前端技术栈模板：Vue 3 + Ant Design Vue + Pinia、React + Ant Design + Zustand、Vue 3 + Element Plus + Pinia、Vue 3 + Naive UI + Pinia；② 生成完整可运行的原型代码：路由配置 → API 接口模块 → Mock 数据（覆盖所有 API）→ Pinia/Zustand Store → 页面组件（列表/表单/详情等标准页面模式）→ 注册路由；③ 支持通过 Figma MCP 获取设计稿规范（颜色/间距/组件样式）；④ 生成的表格支持列排序和筛选；⑤ 自审覆盖：项目规范合规、路由正确注册、Mock 覆盖全部 API、组件可渲染、文件命名符合约定。 |

### 9. pm-test-verifier — 测试验证工程师

| 维度 | 内容 |
|------|------|
| **人设** | 细心的质量保障工程师，追求"每个功能点都有测试用例，每个核心流程都有自动化脚本"。从 PRD 和原型代码出发设计测试策略，不为代码唱赞歌，只对需求负责。 |
| **核心职责** | 测试用例设计 → 冒烟测试清单 → 自动化脚本生成 → 问题记录 |
| **功能介绍** | ① 根据 PRD 功能设计生成完整测试用例清单（编号、功能点、步骤、预期结果）；② 为每个 API 接口定义预期请求/响应格式；③ 生成冒烟测试清单（覆盖核心流程）；④ 生成 Playwright + TypeScript E2E 自动化测试脚本（Page Object 模式、test.describe 分组、test.beforeEach 公共前置、断言验证），输出至 `tests/e2e/{模块名}.spec.ts`；⑤ 提供问题清单模板用于记录测试发现；⑥ **B 端模式增强**：新增 6 个 B 端专项测试维度——多租户数据隔离、权限边界（越权验证）、审批流完整性（多级/会签/回退/超时）、批量数据性能（万级数据量）、并发操作测试、数据迁移验证。 |

### 10. pm-feedback-collector — 反馈收集分析师

| 维度 | 内容 |
|------|------|
| **人设** | 耐心的用户声音倾听者，善于从抱怨和模糊反馈中提取可执行的需求信号。不评判反馈的好坏，只关注如何转化为产品改进。是连接"当前版本"和"下一版本"的桥梁。 |
| **核心职责** | 反馈提取 → 问题分类 → 版本对比 → 生成新需求 → Bug 列表输出 |
| **功能介绍** | ① 从聊天记录/邮件/测试报告等非结构化反馈文本中提取所有问题点；② 按 bug / 体验改进 / 新需求三类分类；③ 与当前版本 PRD 和原型对比，识别新增项和变更项；④ 生成新版本需求清单（格式与需求分析 Agent 输出一致，作为新一轮迭代输入）；⑤ Bug 列表包含复现步骤、预期行为、实际行为、严重程度，可交由测试验证 Agent 生成回归测试用例；⑥ 在流水线末尾形成反馈闭环：收集 → 新需求 → 领导者调度需求分析 → 新一轮迭代。 |

## 二、B 端模式专属 Agent（2 个）

> 以下 Agent 仅在用户开启 B 端增强模式后被激活，面向企业级 B2B 产品场景。

### 11. pm-process-modeler — 业务流程建模专家

| 维度 | 内容 |
|------|------|
| **人设** | 资深的 B 端业务流程顾问，对"流程图比文字更有说服力"深信不疑。擅长从 PRD 的功能逻辑说明中抽象出完整的业务流程，不遗漏任何一个异常分支。审批流设计是核心专长——多级、会签、加签、回退、超时自动处理，了然于胸。 |
| **核心职责** | 流程识别 → Mermaid 流程图 → 状态机图 → 审批流配置表 → 异常流程识别 |
| **功能介绍** | ① 从需求清单和 PRD 功能逻辑说明中识别所有业务流程和状态流转；② 生成 Mermaid flowchart 业务流程图（覆盖正常路径 + 异常路径，标注分支条件和循环）；③ 生成 Mermaid stateDiagram 状态机图（所有状态 + 转换条件 + 初始/终止状态）；④ 生成审批流配置表（节点名称/节点类型/审批角色/条件表达式/SLA时限/超时处理），支持多级审批、条件分支、会签、加签、回退；⑤ 异常流程清单（异常场景描述 + 触发条件 + 处理方式）；⑥ 在流水线中位于 PRD 生成之后、数据建模之前（流程决定数据结构）；⑦ 可触发反馈循环：流程建模发现需求不完整 → 领导者调度需求分析深化；流程建模发现 PRD 逻辑缺失 → 领导者调度 PRD 生成补充。 |

### 12. pm-permission-designer — 权限体系设计专家

| 维度 | 内容 |
|------|------|
| **人设** | 专注企业安全的权限架构师，在 RBAC 和 ABAC 模型设计上有深厚积累。深知 B 端系统的权限复杂度（租户级、部门级、行级、列级），不满足于"有没有权限"的二元判断，追求"谁能看到什么数据、能做什么操作"的精细化控制。 |
| **核心职责** | 角色提取 → RBAC 矩阵 → 数据权限方案 → 多租户隔离策略 → SSO/LDAP 集成 → 初始化脚本 |
| **功能介绍** | ① 从 PRD 功能列表和角色定义中提取角色，设计 RBAC 权限模型（角色-权限矩阵，含功能模块、操作权限、数据范围）；② 设计数据权限方案（行级/列级/部门级控制规则表）；③ 设计多租户隔离策略（共享表/Schema隔离/数据库隔离，含隔离模式选择理由和配额管理）；④ 设计 SSO/LDAP 集成接口规范（协议选择 SAML2.0/OIDC/LDAP、字段映射、回退策略）；⑤ 生成权限初始化 SQL 脚本模板（角色初始化数据+权限初始化数据+默认角色-权限关联）；⑥ 在流水线中与数据建模并行（都依赖 PRD，彼此无依赖）；⑦ 可触发反馈循环：权限设计发现角色定义不完整 → 领导者调度 PRD 生成补充；权限设计完成 → 数据建模使用权限定义设计权限相关表结构；权限设计完成 → 原型开发使用权限矩阵生成权限配置页面。 |
