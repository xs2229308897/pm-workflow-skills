# B 端 PM 工作流增强设计文档

> 日期：2026-05-26
> 状态：已确认
> 范围：P0+P1 增强 + 2 个新 Skill

## 背景

当前 PM 工作流技能库覆盖通用产品开发流程（需求→PRD→原型→测试→反馈），但缺少 B 端产品的三个核心支柱：架构（多租户/权限）、集成（企业系统对接）、治理（合规/安全/审计）。

本次改进采用路径 B：增强现有 Skill 的 B 端能力 + 新增 2 个核心 Skill，保持父子 Agent 架构和动态反馈循环模式不变。

## 核心架构不变

- pm-leader 仍为单一入口
- 子 Agent 通过 Agent() 工具分发
- 4 状态码（DONE/DONE_WITH_GAPS/BLOCKED/NEEDS_CONTEXT）驱动动态编排
- 双层经验教训架构（全局+本地）
- 新增 Skill 注册到 pm-leader 的意图识别表和并行执行规则

## B 端模式开关设计

默认不开启 B 端增强。pm-leader 启动时在首次检查中新增一项：

### 检查 6：是否开启 B 端增强模式

向用户展示：

```
是否开启 B 端增强模式？

开启后，以下能力将被激活：
  - PRD 新增 4 个 B 端标准章节（多租户架构、权限矩阵、系统集成、部署方案）
  - 数据建模使用 B 端数据模式（多租户隔离、审计字段、数据权限）
  - 需求分析适配 B 端输入源（RFP、流程图、组织架构）
  - 风险评估新增 B 端风险维度（合规、迁移、集成、割接）
  - 测试验证新增 B 端测试场景（多租户隔离、权限边界、审批流）
  - 新增流程建模和权限设计两个子 Agent

  1. 开启 B 端增强
  2. 不开启（使用标准模式）
```

**行为：**
- 用户选择 1 → 将 `B_MODE: true` 写入 `docs/superpowers/pm-workflow-state.md`
- 用户选择 2 → 将 `B_MODE: false` 写入（或不写，默认 false）
- 后续启动不再询问，除非用户主动说"切换项目类型"或"开启/关闭 B 端模式"
- 选择结果影响子 Agent 获得的 prompt 内容（B 端章节是否注入）

### 子 Agent 行为差异

| 场景 | B 端模式开启 | B 端模式关闭 |
|------|------------|------------|
| pm-prd-writer | 包含 12 个章节（含 4 个 B 端章节） | 仅包含 8 个标准章节 |
| pm-data-modeler | 使用 B 端数据模式 + 通用实体模板 | 使用标准数据建模 |
| pm-requirement-analysis | 适配 B 端输入源 + B 端隐含需求 | 标准输入处理 |
| pm-risk-assessor | 包含 10 个风险维度（含 5 个 B 端维度） | 仅包含 5 个标准维度 |
| pm-test-verifier | 包含 B 端测试场景 | 标准测试场景 |
| pm-process-modeler | 可被调度 | 不可被调度（意图识别不注册） |
| pm-permission-designer | 可被调度 | 不可被调度（意图识别不注册） |

## 改进范围

### P0 增强：pm-prd-writer

**变更内容：**

1. PRD 标准章节新增 4 个 B 端章节：
   - 9. 多租户架构方案（租户隔离模式、租户管理、配额管理）
   - 10. 权限矩阵（角色×功能×数据范围 三维矩阵、SSO/LDAP 集成）
   - 11. 系统集成接口规范（API 契约、Webhook 事件、数据同步策略）
   - 12. 部署与运维方案（部署方式、环境要求、监控告警）

2. 增强"非功能性需求"章节：
   - 可用性：SLA 指标、故障恢复时间
   - 安全性：数据加密（传输/存储）、审计日志、数据脱敏
   - 可扩展性：并发用户数、数据量增长预期

3. 增强"功能逻辑说明要求"：
   - 增加：审批流设计（多级/条件分支/会签/加签/回退/超时自动处理）
   - 增加：数据权限逻辑（行级/列级/部门级）

4. 增强"自审清单"：
   - 多租户隔离方案是否明确？
   - 权限矩阵是否覆盖所有角色和功能？
   - 集成接口是否定义了契约和错误处理？
   - 非功能性需求是否有量化指标？

### P0 增强：pm-data-modeler

**变更内容：**

1. 新增处理流程步骤：
   - 步骤 2.5：判断是否需要多租户支持，选择隔离模式
   - 步骤 2.6：为每个实体添加审计字段模板
   - 步骤 2.7：识别是否需要数据权限字段

2. 新增 B 端数据模式知识：
   - 多租户-共享表（tenant_id 字段，查询强制过滤）
   - 多租户-Schema 隔离（每租户独立 Schema）
   - 多租户-数据库隔离（每租户独立数据库）
   - 审计字段模板（created_by, created_at, updated_by, updated_at, deleted_at）
   - 数据权限字段（org_id, data_scope）
   - 软删除模式（deleted_at + 查询过滤）

3. 新增 B 端通用实体模板：
   - 用户表（users）、角色表（roles）、权限表（permissions）、用户角色关联表（user_roles）
   - 组织架构表（organizations）、审批记录表（approval_records）、操作日志表（operation_logs）

4. 增强自审清单：
   - 是否为所有实体添加了审计字段？
   - 多租户隔离模式是否明确？
   - 是否包含 B 端通用实体？
   - 数据权限字段是否设计？

### P1 增强：pm-requirement-analysis

**变更内容：**

1. 增强输入类型：
   - 客户 RFP/招标文件
   - 业务流程图（As-Is 现状流程）
   - 现有系统操作手册
   - 客户组织架构描述
   - 行业法规/合规要求文档

2. 增强需求分类维度：
   - 按角色：管理员/操作员/审计员/访客
   - 按租户层级：平台级/租户级/部门级
   - 按业务流程：流程节点/审批规则/异常处理

3. 增强隐含需求补充规则（B 端特有）：
   - 数据导出（Excel/CSV/PDF）
   - 操作日志（谁在什么时间做了什么）
   - 批量操作（批量导入/批量审批/批量分配）
   - 异常恢复（操作撤回/数据回滚/审批回退）
   - 多端适配（PC + 移动端 + 大屏）
   - 通知机制（站内信/邮件/短信/企业微信/钉钉）

### P1 增强：pm-risk-assessor

**变更内容：**

新增风险维度：

| 风险类型 | 评估内容 | 触发条件 |
|---------|---------|---------|
| 合规风险 | 是否满足行业法规（等保/GDPR/SOC2/HIPAA） | 涉及数据存储/跨境/敏感信息 |
| 数据迁移风险 | 源系统数据质量、字段映射复杂度、回滚可行性 | 替换旧系统 |
| 集成风险 | 第三方系统 API 稳定性、文档完整性、联调周期 | 与外部系统对接 |
| 客户定制化风险 | 需求蔓延概率、定制化对产品化的影响 | 多客户需求差异大 |
| 上线割接风险 | 业务中断时长、数据一致性、回滚预案 | 替换生产系统 |

增强输出格式：
- 风险矩阵增加"风险缓解方案"列
- 增加"上线前风险检查清单"

### P1 增强：pm-test-verifier

**变更内容：**

新增 B 端测试维度：
- 多租户数据隔离测试（租户 A 不能看到租户 B 数据）
- 权限边界测试（越权操作验证）
- 审批流完整性测试（多级/会签/回退/超时）
- 批量数据性能测试
- 并发操作测试
- 数据迁移验证测试模板

### 新增 Skill：pm-process-modeler

**职责：** 从需求描述中提取业务流程，生成流程图、状态机图、审批流配置表

**输入：**
- 需求清单（来自需求分析 Agent）
- PRD 中的功能逻辑说明（来自 PRD 生成 Agent）

**处理流程：**
1. 识别需求中的业务流程和状态流转
2. 生成 Mermaid flowchart 流程图
3. 生成 Mermaid stateDiagram 状态机图
4. 生成审批流配置表（节点/条件/角色/SLA 时限）
5. 识别异常流程和边界条件

**输出格式：**
1. 业务流程图（Mermaid flowchart）
2. 状态机图（Mermaid stateDiagram）
3. 审批流配置表（节点类型/审批角色/条件表达式/SLA 时限/超时处理）
4. 异常流程清单

**自审清单：**
- 流程图是否覆盖所有正常路径和异常路径？
- 状态机是否包含所有状态和转换条件？
- 审批流是否支持多级/条件分支/会签/加签/回退？
- SLA 时限是否合理？

**汇报格式：** DONE | DONE_WITH_GAPS | BLOCKED | NEEDS_CONTEXT

**在流水线中的位置：** PRD 生成之后、数据建模之前（流程决定数据结构）

**并行规则：** 无（必须串行：PRD 生成 → 流程建模 → 数据建模）

**反馈循环：**
- 流程建模发现需求不完整 → 领导者调度需求分析深化
- 流程建模发现 PRD 逻辑缺失 → 领导者调度 PRD 生成补充
- 流程建模完成 → 数据建模使用流程定义设计数据结构

### 新增 Skill：pm-permission-designer

**职责：** 设计 RBAC/ABAC 权限模型、数据权限方案、多租户隔离策略

**输入：**
- PRD 中的功能列表和角色定义（来自 PRD 生成 Agent）
- 客户组织架构描述（来自需求分析 Agent）

**处理流程：**
1. 提取 PRD 中的角色和功能列表
2. 设计 RBAC 权限模型（角色-权限矩阵）
3. 设计数据权限方案（行级/列级/部门级）
4. 设计多租户隔离策略（共享表/Schema/数据库）
5. 设计 SSO/LDAP 集成接口规范
6. 生成权限配置表和初始化数据

**输出格式：**
1. 角色-权限矩阵（角色×功能×操作×数据范围）
2. 数据权限规则表
3. 多租户架构方案文档
4. SSO/LDAP 集成接口规范
5. 权限初始化 SQL 脚本模板

**自审清单：**
- 角色是否覆盖所有业务角色（管理员/操作员/审计员/访客）？
- 权限是否覆盖所有功能模块？
- 数据权限是否支持行级和列级控制？
- 多租户隔离模式是否与部署方案匹配？
- SSO/LDAP 接口是否符合目标系统的协议？

**汇报格式：** DONE | DONE_WITH_GAPS | BLOCKED | NEEDS_CONTEXT

**在流水线中的位置：** PRD 生成之后，与数据建模并行

**并行规则：** 权限设计 ∥ 数据建模（都依赖 PRD，但彼此无依赖）

**反馈循环：**
- 权限设计发现角色定义不完整 → 领导者调度 PRD 生成补充
- 权限设计完成 → 数据建模使用权限定义设计权限相关表结构
- 权限设计完成 → 原型开发使用权限矩阵生成权限配置页

## pm-leader 变更

### 启动流程变更

在首次启动检查中新增"检查 6：是否开启 B 端增强模式"（见上方"B 端模式开关设计"章节）。

B 端模式状态写入 `docs/superpowers/pm-workflow-state.md`，格式：
```markdown
## B 端模式：已开启 | 未开启
```

### 意图识别表新增

| 用户输入特征 | 判断意图 | 执行动作 |
|-------------|---------|---------|
| "画流程" / "审批流" / "状态机" / "流程图" | 流程建模 | 调用流程建模 Agent |
| "权限设计" / "多租户" / "RBAC" / "权限矩阵" | 权限设计 | 调用权限设计 Agent |

### 并行执行规则更新

**可并行的组合**（新增）：
- 权限设计 ∥ 数据建模（都依赖 PRD，但彼此无依赖）

**必须串行的组合**（新增）：
- PRD 生成 → 流程建模
- 流程建模 → 数据建模

**更新后的默认执行顺序**：
1. 需求分析 ∥ 竞品分析（并行）
2. PRD 生成
3. 流程建模（串行）
4. 权限设计 ∥ 数据建模（并行）
5. 风险评估（可与步骤 4 并行）
6. 原型开发
7. 测试验证
8. 反馈收集 → 回到第 1 步

### 动态反馈循环规则新增

| 源 Agent | 反馈内容 | 领导者调度目标 |
|----------|---------|--------------|
| 流程建模 | 需求描述不完整 | → 需求分析深化 |
| 流程建模 | PRD 逻辑缺失 | → PRD 生成补充 |
| 流程建模 | 流程定义完成 | → 数据建模 + 权限设计使用 |
| 权限设计 | 角色定义不完整 | → PRD 生成补充 |
| 权限设计 | 权限设计完成 | → 数据建模使用 |
